# Internationalization

OSM requires `pelican-tabular>=0.9.0` for the shared
`pelican.plugins.tabular.i18n` API. The lockfile uses the published PyPI package.
Install and test with the normal project environment:

```sh
uv sync --locked --no-sources
uv run --locked poe lint
uv run --locked poe cover
```

## Component language

Both shortcodes accept `lang="ja"`. Language priority is shortcode → article/page
`Lang` → current build's `DEFAULT_LANG` → English. Tables, captions, popup fields,
map controls and photo lightboxes use that same component language. JavaScript
does not substitute the reader's browser language.

UI catalogs cover English, Traditional Chinese and Japanese. `zh_TW` is
normalized to `zh-TW`; `zh-TW`/`zh-Hant` and legacy `zh` select Traditional
Chinese. `zh-Hans`/`zh-CN` and other unsupported languages fall back to English.
Exact matches precede compatible same-script resources.

Schema `x-osm-list-i18n.title` uses the shared matcher. Both popup and table
labels follow: translated schema title → schema `title` → `OSM_LIST_FIELD_LABELS`
→ built-in label/key. `OSM_LIST_FIELD_LABELS` values may be strings or locale maps.
Explicit empty translations are preserved.

```python
OSM_LIST_FIELD_LABELS = {"name": {"zh-TW": "名稱", "ja": "名前"}}
OSM_MESSAGES = {"resetView": {"zh-TW": "重設範圍", "ja": "表示範囲を戻す"}}
```

`OSM_MESSAGES` uses the keys in the package's `messages.json`, including
`placeCount`, `more`, `allLayers`, `loadError`, `noPlaces`, `viewInTable`, `layer`,
`clearFilter`, `fullscreen`, `resetView`, `close`, `previous`, `next`, `photo`,
`photoCount`, `loading`, `link`, `zoomIn`, `zoomOut` and `popupClose`.
`field.<name>` keys provide built-in field labels. Counts accept plain templates
or `{ "plural": "n", "forms": { "one": "{n} place", "other": "{n} places" } }`.
`photoCount` uses `{shown}` and `{total}`. Invalid language tags, template types
and placeholders produce build errors with setting paths.

`OSM_LIST_GROUP_COUNT_TEMPLATE` remains a trusted HTML template; `""` hides group
counts. `window.OSM_I18N`, set before the script loads, still overrides browser
messages, including function-valued `placeCount`. It does not change generated
HTML captions or headers; use `OSM_MESSAGES` for build-time and browser parity.
For popup field labels, schema/configured Python labels take precedence over
legacy JS `fieldLabels`, which takes precedence over the catalog.

For old markup with no component payload, the generated script supplies the
build's default catalog and reads the containing HTML language. Rebuild HTML
and assets together to get per-component localization.

## Place data translations

Translation is explicitly enabled and limited to scalar text:

```python
OSM_TRANSLATIONS = {
    "field": "translations",
    "fields": ["name", "note"],
    "source_lang": "zh-TW",
    "aliases": {"ja": {"name": "name_ja"}},  # optional existing-field mapping
}
```

```yaml
- id: station
  name: 東京車站
  lat: 35.6812
  lon: 139.7671
  note: 來源備註
  translations:
    ja:
      name: 東京駅
```

Record translations override alias mappings. Missing translations keep the
source text and its actual `lang`; an empty translation remains empty. Raw
records/caches are never changed. The translation block is not exposed as a
popup field or table column. Ordinary dictionaries are not interpreted as
translations when this feature is disabled.

IDs, coordinates, numeric values, links and tags remain canonical. Grouping
and map-layer fields must not be translated; use translated schema labels.
Nested item rows are projected after expansion. Tables and markers retain
source IDs/slugs, and map fragments can still refer to the source name.
Photo lookups use the same stable identity.

When translations are enabled, each used component locale has its own
`static/places/i18n/<locale>/<source>.geojson` output. There is no shared
untranslated GeoJSON at the old path in this mode. Without translations the
existing `static/places/<source>.geojson` paths remain unchanged.
The default URL prefix is `SITEURL + "/static"`; explicitly configured
`OSM_STATIC_PREFIX` still wins (including deployments using a CDN).
Each build exports from its own resolver/root and URL context.

Browser table and layer sorting uses the component locale; initial Python
group/sort order retains its existing deterministic behavior. Generated table
text is available without JavaScript and can be indexed by Pagefind. Site-level
Pagefind language routing and alias indexing are separate configuration.
